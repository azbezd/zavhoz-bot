# Развёртывание и эксплуатация

Для тех, кто держит бота на сервере. Быстрый запуск на своей машине — в [README](../README.md#установка).

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Что делает |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | токен бота от @BotFather |
| `OPENAI_API_KEY` | да | — | ключ OpenAI API |
| `ALLOWED_TELEGRAM_USER_IDS` | да | пусто | id пользователей через запятую; пусто — бот никому не отвечает |
| `OPENAI_MODEL` | нет | `gpt-5.4-mini` | модель для разбора и ответов |
| `OPENAI_BASE_URL` | нет | `https://api.openai.com/v1` | совместимый с OpenAI адрес API |
| `INVENTORY_ENABLE_WEB_SEARCH` | нет | `1` | поиск в сети при обогащении карточек |
| `INVENTORY_DB` | нет | `inventory_bot/inventory.db` | путь к базе SQLite |
| `INVENTORY_REPO_DIR` | нет | текущая папка | куда складываются фото и выгрузка данных |
| `INVENTORY_AUTO_GIT` | нет | `0` | `1` — после применения черновика коммитить и пушить данные |
| `ZAVHOZ_SITE_BASE` | нет | каталог автора | адрес вашего каталога: на него ведут ссылки из ответов бота |
| `HTTPS_PROXY`, `NO_PROXY` | нет | — | прокси для исходящих запросов, если OpenAI недоступен из сети сервера |

Шаблон — [`inventory_bot/env.example`](../inventory_bot/env.example). На сервере храните файл вне репозитория с правами `0600`.

## Служба systemd

```ini
# /etc/systemd/system/zavhoz-bot.service
[Unit]
Description=Zavhoz Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
EnvironmentFile=/etc/zavhoz-bot.env
WorkingDirectory=/opt/zavhoz/zavhoz-bot
ExecStart=/usr/bin/python3 -m inventory_bot.bot
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now zavhoz-bot
journalctl -u zavhoz-bot -f
```

Обновление: `git pull` в рабочей папке и `systemctl restart zavhoz-bot`.

## Каталог

```bash
python3 -m inventory_bot.build_site /путь/к/клону-сайта
```

Генератор сначала строит результат во временной папке из согласованного снимка SQLite, затем заменяет только `index.html`, `item/`, `404.html`, `assets/`, `photos/` и `.nojekyll`. Посторонние файлы и `.git` сохраняются. Локальная замена нескольких папок не является общей атомарной операцией; GitHub Pages публикуется отдельным коммитом.

Фотографии выпускаются только при наличии записи в `public_assets` с совпадающим SHA-256. Перед внесением такой записи нужно посмотреть файл: в нём не должно быть заказа, адреса, цены или других приватных данных. Изменённые байты требуют повторной проверки. Нельзя разрешать папку целиком. `public_visible=0`, `quarantine`, `lost`, `retired` исключаются из каталога.

Скрипт [`scripts/publish-site.sh`](../scripts/publish-site.sh) использует `flock`, промежуточную сборку и проверку ветки. Он не проверяет mtime основного файла: актуальные данные могут находиться в WAL. `CATALOG_PUBLISH_BRANCH` задаёт разрешённую ветку публикации; для подготовки PR укажите свою ветку. Переход к main выполняет владелец после проверки.

## Данные в отдельном репозитории

`/export` выгружает базу в файлы внутри `INVENTORY_REPO_DIR`. При `INVENTORY_AUTO_GIT=1` бот после каждого применённого черновика делает `git add`, `git commit` и `git push` в этой папке. Для этого дайте серверу deploy key с правом записи только в репозиторий данных — не в репозиторий кода.

## Если бот молчит

1. `journalctl -u zavhoz-bot -n 50` — повторяющиеся `timed out` у `getUpdates` значат, что сервер не достаёт до Telegram: проверьте сеть и прокси.
2. В логе есть `message … user_id=…`, а ответа нет — этого id нет в `ALLOWED_TELEGRAM_USER_IDS`.
3. Ошибки `OpenAI HTTP 4xx` — ключ, модель или `OPENAI_BASE_URL`.

## Резервирование и восстановление

```bash
INVENTORY_DB=/opt/zavhoz/inventory.db python3 -m inventory_bot.backup /secure/backups/inventory-before.sqlite
python3 -m unittest discover -s tests -v
```

SQLite backup включает WAL и проверяет целостность; существующую копию не перезаписывает. [`scripts/backup-inventory.sh`](../scripts/backup-inventory.sh) — пример ежедневной задачи с правами 0600. Фото и секреты резервируются отдельно. Автоматического удаления старых копий нет.

Для полного восстановления остановите службу, сохраните текущее состояние отдельной копией, разверните проверенный SQLite backup вместе с соответствующими фотографиями. Не копируйте один `inventory.db` поверх открытого WAL. Полный JSON-экспорт восстанавливается функцией `backup.restore_snapshot` только в пустую схему и содержит складские таблицы; черновики, диалоговые сессии и журнал Telegram сохраняет именно SQLite backup.

## Закупки и подтверждённые знания

`python3 -m inventory_bot.import_purchases /private/reviewed-manifest.json` применяет проверенный манифест одной транзакцией. `event_key` обеспечивает повторяемость: повторный запуск ничего не добавляет, изменившееся свидетельство с тем же ключом отклоняется. Манифесты и `purchase_events` приватны; их нельзя коммитить в репозиторий кода или сайта.

`quantity_basis=purchase` означает расчёт по покупке без физической проверки. `ordered` и `quarantine` имеют нулевой свободный остаток. У ошибочной поставки фактическая модель остаётся неизвестной, даже если в заказе указана конкретная. `reviewed_at` защищает проверенный текст от автоматического обогащения.

## Повторная доставка Telegram и сбои

`processed_updates` фиксирует update до обработки и предотвращает повторное изменение склада после перезапуска. Записи `processing` после аварии и `failed` требуют ручной проверки результата: автоматический повтор может повторно изменить склад или отправить сообщение. Это обработка не более одного раза, а не гарантия доставки ответа. Тесты Telegram используют подмену API и не отправляют пользователям сообщения.

Модельные вызовы пока синхронные: длительное обогащение задерживает обработку следующих сообщений. Очередь задач и объединение медиаальбомов остаются отдельными улучшениями. Публичные файлы, попавшие в старую историю Git, не исчезнут после обычного удаления в новой версии; очистка истории требует отдельного решения владельца.
